01 / The friction

一开始，我只是想解决一个很简单的问题。

01Prompt 每次都要重新写
02风格、角色与叙事每次都漂移
03AI 常把文章直接做成 bullet points
04中文、页间节奏与视觉质量需要反复补救
05每次都得重新把隐性经验说给 AI 听

ONE-OFF LABOR

一次性 prompt，等于一次性劳动。经验还在我脑子里，没有进系统。

THE REAL PROBLEM

问题不是 Prompt 不够长，而是缺少一套长期可复用的规则系统。

02 / The shift

从 Prompt，到 Skill。

Prompt

ONE-OFF INSTRUCTION

  • 一次性指令
  • 依赖当前上下文
  • 规则混在一起
  • 结果容易漂移
  • 难以维护和组合
→

Skill

REUSABLE OPERATING SYSTEM

  • 长期规则
  • 模块化加载
  • 按任务组合
  • 可维护、可迭代
  • 可被 Agent 自动读取

Skill = 把经验变成 AI 可以重复执行的 SOP。

06 / Character DNA

怎么保证小黄还是小黄？

空心爱心天线 竖椭圆眼 不规则种子身体 细黑四肢
不可以改变暖黄色、略倾斜的种子轮廓；爱心天线；宽间距黑色竖椭圆眼；微笑、腮红和细黑四肢。
可以改变动作、表情、场景、服装、媒介、光线、构图与支持故事的物件。
优先级身份锚点 → 用户明确的变量 → 当前页面语义 → 风格与装饰。
角色职责筛、捞、扛、拆、接、压、修、推、记录；小黄必须承担关键动作，不能只站在角落。

可以换世界，不能换身份。

07 / Visual DNA

怎么保证每一页属于同一个世界？

一致性不是每一页都长得一样，而是先把可复用的视觉不变量写进 Style Lock：画布、颜色、线条、留白、角色与文字预算全部先确定。

Canvas：标准 Deck 为 16:9，推荐 1920 × 1080；暖白背景占主导，主动作占画面 40%–60%，至少保留三分之一安静空间。

09 / Semantic layout

Layout 不是模板决定的，而是内容关系决定的。

点击任意结构，看它对应的画面动作。一页只解释一种关系。

先问：这一页要解释哪种关系？

10 / One image, step by step

一张图是怎么生成出来的？

ONE RAW SENTENCE

“AI Skill 的本质，是把个人经验变成机器可以重复执行的规则。”
01

提取核心关系

经验 → 规则。核心不是解释 AI，而是让“从混乱到可复用”的转化可见。

02

选择 Archetype

选 Transformation，而不是普通流程图：画出前后两个状态和中间的搬运动作。

03

安排小黄动作

小黄把一堆杂乱的“经验纸条”搬进一个标记为“规则”的低科技盒子。

04

加入 Style Lock

暖白画布、轻手绘黑线、黄色只给小黄、中文短标注、足够留白。

05

生成并 QA

检查身份锚点、标注、关系是否清楚，以及它是否能和整套页面放在一起。

结果：图像不是“文章的缩略图”，而是一个能把抽象关系讲明白的视觉句子。

11 / QA is part of the skill

生成不是结束，验收才是结束。

output-quality.md 明确把验收写进工作流：不是看一张图“还不错”就交付，而是确认每张图和整套图都稳定成立。

12 / Make your own

而是一套工作流。
