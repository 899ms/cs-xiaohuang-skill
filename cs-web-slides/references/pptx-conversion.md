# PPTX 转网页

## 目标

转换是“保留内容与品牌资产后的网页再设计”，不是逐像素截图复制。优先保留原来的信息顺序、核心文字、产品截图、照片、logo 和必要的图表含义；重新建立更清晰的网页视觉系统与动效。

## 提取

在 PPTX 所在目录执行。把下例的 `<skill 目录>` 替换为已安装的 `cs-web-slides` 路径：

```powershell
& "<skill 目录>\scripts\extract-pptx.ps1" -PptxPath .\source-deck.pptx -OutputDir .\extracted-deck
```

脚本会生成：

- `slides.md`：逐页文字与图片引用；
- `manifest.json`：可用于大纲确认的结构化清单；
- `assets/`：从 PPTX 原封不动提取的媒体文件。

脚本不会覆盖已有输出目录；用户明确需要覆盖时才传入 `-Force`。如果 PPTX 包含 SmartArt、嵌入对象、图表、公式、复杂分组、媒体或动画，脚本会尽力列出文字和图片，但可能无法还原对象语义。此时在生成前检查原始页面并手动补充要保留的含义。

## 转换流程

1. 运行提取脚本，先核对页数、标题、文字与媒体数量。
2. 让用户确认信息取舍和三个设计方向；不要在未确认的情况下抛弃关键图、logo 或截图。
3. 将选中的图片从 `extracted-deck/assets/` 复制或保留在新 deck 的 `assets/` 中，用相对路径引用。
4. 按原始页序建立网页 slide；当原页面过密时拆分为连续网页页，并在交付说明中标明。
5. speaker notes、隐藏页和 PPT 原生转场不是默认保留项；用户明确需要时，在 HTML 注释、演讲者视图或新的网页动效中分别实现。

## 交付前检查

- 每一张应保留的图片、截图、logo 均实际加载，不是空框或重新生成的替代品。
- 幻灯片标题与事实没有因提取顺序错误而错配。
- 图片文件名使用相对路径，部署/导出时仍可访问。
- 网页只含用户允许公开的资源和内容。
